## 2. 数据如何从界面进入算法

用户编辑拓扑 → QML 调用 `GraphBackend` → 后端维护 `Graph` → `GraphBackend::run` 根据算法名调用四个独立函数 → 返回 `Trace` → 转换为 `QVariantMap` → 时间轴逐项播放 `TraceStep` → 画布按 id 高亮节点和边。

`RouterNode` 保存节点 id、名称、坐标。`RouterLink` 保存链路 id、两端 `u/v`、造价 `cost`、容量 `capacity`、方向 `directed`、以及是否具有对应权值的 `hasCost/hasCapacity`。节点删除后 id 不一定连续，算法用 `indicesOf` 把 id 映射到连续数组下标。

`Trace.value` 是最终算法值。`TraceStep` 是每一步的独立显示快照：`visitedNodes` 表示访问/确定节点，`selectedEdges` 表示选边，`pathNodes/pathEdges` 表示路线，`distances` 表示距离，`linkFlows/residualArcs/pathArcs` 表示流量与剩余网络。创建快照不决定贪心选择；计算和展示有明确分工。

## 3. Prim：从一个起点向外扩树

目标是在可用于建设的链路上连接所有节点，使总造价最小。只参与 `hasCost` 为真的边。建设连接按无向图处理，即使某条通信链路设置了方向，MST 仍将其视为两端可建设的连接；最小生成树不是有向最小树形图。

1. 检查起点存在。`seen` 初始只有起点，`selected` 为空，`total=0`。
2. `addFrontier` 扫描边，把当前节点通向树外节点的候选边放入最小堆。比较器反向比较造价，将最低造价放在堆顶；平局按链路 id 排序。
3. 弹出最便宜候选。目标已在 `seen` 中说明这条候选已失效，加入会成环，直接跳过。
4. 接入树外目标，记录边、累计造价，再添加新节点的边界候选。
5. 接受 `V-1` 条边即完成。堆耗尽但边数不足，则网络不连通，返回错误。

正确性讲解：当前已连接节点与其余节点形成一个割，每次选择该割上最轻的可用边，符合最小生成树的割性质。实现中的惰性删除允许堆里有旧候选，但 `seen` 检查保证不会真正接入成环边。

复杂度应结合这份代码回答：有堆，但每接入一个节点都扫描全部边，主计算约 `O(VE + E log E)`，并非邻接表优化版的 `O(E log V)`。演示快照还会复制已访问节点和选边。

## 4. Kruskal：按造价排序，连接不同分量

目标同 Prim；同样仅用具有造价的链路，并按无向建设连接处理。它不依赖起点。

1. 收集边的下标并按造价、链路 id 排序，保持原图的顺序和 id 不变。
2. `parent[i]=i`，每个节点是单独的连通分量。
3. `find` 沿父指针查根，并将当前节点挂到祖父节点，实现路径折半。
4. 考察一条边，两端同根就跳过，否则接受该边，并用 `parent[a]=b` 合并两分量。
5. 接受 `V-1` 条边即可结束；不足则报告不连通。

正确性讲解：选边始终无环，形成森林；从便宜到昂贵连接不同分量，每次选择都是安全边。与 Prim 的差别是 Prim 从一个连通树向外扩展，Kruskal 可以同时维护多棵树再逐步合并。

排序为 `O(E log E)`。这份并查集有路径折半，没有按秩/按大小合并，因此不能把“按秩 + 路径压缩”的 `O(alpha(V))` 结论直接套用。演示用 `visited.contains` 线性查重也有额外开销；不要把优化版教材的复杂度误称为本程序整体耗时。

## 5. Dijkstra：按造价求最短路径

目标是从指定起点到终点，使沿途建设造价之和最小。它只使用 `hasCost` 边，有向边只允许 `u→v`，无向边允许两方向。非负权是前提，由编辑和预设读取入口校验。

1. `distance` 全部置为无穷大，起点置 0；`previousNode/previousEdge` 置 -1，尚无前驱。
2. 每轮线性扫描未确定的节点，选择暂定距离最小者；平局按节点 id 决定。
3. 将该节点标为 `settled`。终点一旦确定即可结束，因为非负边权保证其距离不会再变小。
4. 扫描原图链路找可沿方向通行的邻居，计算 `candidate=distance[current]+cost`。加法先做余量检查避免溢出。
5. 候选严格更小时执行松弛，同时更新距离、前驱节点和前驱边。
6. 从终点沿前驱回到起点，再反转节点和边序列，得到最终路线；若終点仍为无穷大则返回不可达。

`routeTo` 的深度上限是防御性检查。`record` 将内部的无穷大转成 -1，界面用“∞”显示，并保存当前完整距离表。终点提前结束时，其余未确定节点的距离可能仍是暂定值。

本代码没有堆，也没有邻接表，主循环为 `O(V² + VE)`；显示快照和路径重建有额外成本。答辩不要说实现了 `O(E log V)` 的堆优化。

## 6. 最大流：BFS 增广、反向弧、最终分解

目标是按链路容量求源点到汇点的最大吞吐量，忽略建设造价。算法采用 Edmonds–Karp，即每次用 BFS 寻找剩余网络中边数最少的增广路。

### 6.1 剩余网络

`Arc.capacity` 是当前剩余容量，`reverseIndex` 是配对反向弧在对端邻接表中的下标，`linkIndex` 指回原图边，`sign` 指出此弧对原边净流量的增减方向。`addArc` 同时建立容量为 c 的正向弧和初始容量为 0 的反向弧。

反向弧表示能撤销先前分配的流量并重新分配，不代表原图真的新建了一条通信链路。无向链路在两个方向各建一组弧，最终 `flows` 记录抵消后的有符号净流量；负数表示实际沿原记录的 `v→u` 载流。

### 6.2 BFS 与增广

每轮重置 `parent/via`。`parent` 保存前驱节点下标，`via` 保存前驱邻接表中的弧下标。只搜索剩余容量大于零的弧，节点首次发现即标记并入队。到汇点后沿前驱回溯通路，瓶颈为各段剩余容量的最小值。

沿通路更新：`arc.capacity -= bottleneck`、配对反向弧 `+= bottleneck`、原边净流量 `+= sign*bottleneck`。完成整条路径后，`total += bottleneck`。界面逐条边扣减只是教学动画，中途快照尚未完成整轮增广；完成后的 `augment` 才代表一次满足流量守恒的整体结果。

若 BFS 再也到不了汇点，源点在剩余网络中的可达节点形成最小割的源侧。无增广路说明当前流达到最大，由最大流最小割定理可验证结果。

### 6.3 为什么最后显示的彩色路径不一定等于增广历史

结束后将非零净流量按实际方向另建载流图，反复找源汇路线，取沿途最小剩余载流量并扣减，直到分解总量达到 `total`。这一步是对最终流的展示分解，不是重算最大流。历史增广可能包含回退，直接展示全部历史路径会重复计数；无关循环流不列为源汇输送路径。

标准 Edmonds–Karp 增广主算法复杂度是 `O(VE²)`。演示逐步记录剩余弧/流量，最终又进行路径分解；完整程序时间和空间不能只用标准算法的一行复杂度代表。

## 7. 安全通信、AES 和 GCM 的实现边界

`GraphBackend::route` 用 BFS 选择跳数最少的可用路线，遵守方向并跳过已知容量为零的边。它不是 Dijkstra，也不是最大流。未配置容量的造价例题边仍允许连通，因此可以用于安全通信演示。

真实消息加密在 `SecureMessageService.cpp` 中调用 Windows CNG：`BCryptOpenAlgorithmProvider` 选择 AES，设为 GCM，用 256 位密钥与每次新生成的 96 位 nonce，加密得到密文和 128 位认证标签。包格式是 `nonce(12字节) | tag(16字节) | ciphertext`，整体以 Base64 编码。本实验 AAD 为空。

教学计算在 `AesGcmTrace.cpp` 中独立实现，关键位置已有中文注释：

- `multiply8/sbox`：GF(2⁸) 乘法、求逆和仿射变换构造 S 盒。
- `expand`：AES-256 密钥扩展为第 0~14 轮共 15 组轮密钥。
- `encrypt`：初始加轮密钥，加上 14 轮字节替换、行移位、列混合、加轮密钥；第 14 轮省略列混合。矩阵按列存放。
- `multiply128`：GHASH 使用的 GF(2¹²⁸) 乘法。
- `AesGcmTrace::packet`：构造 `J0=nonce||1`，计算 `H=AES_K(0)`，对密文及长度块做 GHASH，标签为 `GHASH XOR AES_K(J0)`。
- 消息首块使用 `nonce||2` 的正向 AES 输出作为密钥流，与明文/密文异或。接收端仍使用正向 AES，不用 AES 逆轮。

认证失败时不返回明文。教学计算与真实 CNG 结果在 `tracePacket` 中交叉核对；教学代码用于显示实际包的计算过程。通信会话与路由均在本机模拟，不是实际联网协议。

## 8. 可现场核对的结果与演示顺序

先载入造价例题：Prim 与 Kruskal 总造价均为 41，Dijkstra 的 R1→R8 距离为 23。再载入修正后的吞吐例题：R1→R8 最大流为 13 包/秒。新图保留 R4→R3（容量 2）、R5→R6（容量 12），不存在旧图的 R2→R4。

建议讲解顺序：数据结构 → 算法独立文件 → 关键循环与状态变量 → 实际界面对应步骤 → 测试核对值。最大流重点展示配对反向弧及瓶颈更新；Dijkstra 展示松弛和前驱；Kruskal 展示判环；Prim 展示边界堆和惰性删除。

测试位置：`tests/tst_graph.cpp` 检查例题值、方向、不可达、流量分解、预设一致性与独立最小割；`tests/tst_secure.cpp` 检查认证、错误密钥、篡改、AES/GCM 计算；画布与真实界面测试分别在 `tst_canvas.cpp`、`tst_layout.cpp`。

## 9. 运行包与源码构建

使用程序：完整解压，双击 `CampusRouter.exe`。Qt DLL、QML 模块、平台插件和 MinGW 运行库随包携带；不能只拷贝 exe。运行不需要安装 Qt、Qt Creator、CMake、Python，也不需要网络。Windows 的系统 DLL 和图形驱动仍由操作系统提供。已验证平台为 Windows 11 64 位。

重新编译源码需要开发环境：Qt 6.11.2 MinGW 64-bit、CMake、C++17 编译器；Qt Creator 可打开源码目录的 `CMakeLists.txt`。`package.ps1` 中开发工具路径需要按目标电脑调整。运行包免安装与编译源码需要 Qt 是两个不同要求。

发布包另附 `免Qt运行验证说明.txt`，记录隔离路径、模块来源检查及静态依赖审计的结果和边界；`verify-portable.ps1` 可在 Windows 上重新执行隔离启动验证，输出诊断记录。
