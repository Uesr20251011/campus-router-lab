校园路由实验室 · 免 Qt 安装运行验证

目标：检查完整 Windows 发布包是否无需安装 Qt/Qt Creator 即可启动并使用核心功能。
运行方法：完整解压，双击 CampusRouter.exe；必须保留全部 DLL、插件与 QML 目录。
已验证平台：Windows 11，64 位。

验证方法
1. 对发布包中所有 EXE/DLL 解析 PE 普通导入与延迟加载导入，检查依赖是否由包自身、Windows System32 或 Windows API-set 合同提供。
2. 把实际压缩包解压到新目录，从解压出的程序启动。
3. 启动环境 PATH 仅保留 Windows 目录；清除 Qt 插件路径、QML 路径和 Qt 平台设置；使用独立临时用户数据目录，并禁用 QML 磁盘缓存。
4. 在原生 Windows 图形环境分别加载造价例题、Prim 结果、Dijkstra 结果、最大流结果、AES/GCM 计算页面与篡改认证失败页面，确认进程成功退出并产生有效截图。
5. 运行期间采样进程已加载模块：Qt、包内声明的动态插件和 MinGW 库必须来自发布包；另外记录 Windows 系统模块、第三方主机软件注入模块及 Qt 插件加载日志，不将主机软件注入模块混称为项目运行依赖。
6. 对照发布包中的源码快照与本次源码，确认核心算法为实际构建版本。

验证结果（2026-10-10，v1.6.1）
- 静态审计 85 个 EXE/DLL、589 项导入依赖，未发现无法由发布包或 Windows 系统提供的依赖。
- 六个原生 Windows 页面均启动并生成有效截图：造价图、Prim、Dijkstra、最大流、AES/GCM 计算、篡改认证失败。
- 运行期间采样到的 Qt DLL、平台/QML 插件和 MinGW 运行库均来自发布包，没有借用本机 Qt 安装目录。
- 主机声效软件注入的外来模块另行记录在本地验证日志中，不作为本项目必须安装的依赖。
- 算法、安全通信、画布、界面布局四组 CTest 全部通过。
- 四份独立算法源码与拆分前的计算语句一致；包内源码和带行号网页逐行对应。
- 发布前再次从最终 ZIP 解压并执行相同隔离验证；结果在本地构建日志中保存。

边界
当前主机安装了 Qt，但测试进程移除了指向其安装目录的路径，实际模块来源检查用于排除借用本机 Qt 库的情况。本次没有可用的干净 Windows 虚拟机，也未在另一台完全未安装 Qt 的实体电脑上执行。因此上述结果是“运行库完整性 + 隔离启动 + 模块来源”的证据，不冒充独立干净系统实测。
系统 DLL、字体与图形驱动由 Windows 提供；不能据此保证所有 Windows 版本或所有显卡组合。Linux/macOS 不能运行本 Windows EXE。安全通信调用 Windows bcrypt.dll，不需要另装 OpenSSL。

复查
发布包附 verify-portable.ps1。通过 PowerShell 执行该文件即可重做路径隔离、六个功能页面启动与模块来源检查；输出目录中包含截图、插件日志及 runtime-report.json。脚本运行结束会恢复修改过的进程环境变量。
静态审计工具位于“答辩资料/源码/tools/audit_pe_dependencies.py”，仅供开发人员进一步复查，运行应用本身不需要 Python。
