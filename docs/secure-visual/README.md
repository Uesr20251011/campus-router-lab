# 安全通信：网络画布与当前步骤

原网络画布和工具栏保留在主界面，包沿实际链路移动。侧边只保留一张当前步骤卡片，按“输入消息 → 途中观察 → 接收解密”更新。密钥、明文对照与测试记录集中在“设置”中。界面只使用路由器术语。

## 演示顺序

1. 在网络界面载入例题 2，点击锁形工具，发送端设为 1、接收端设为 8。默认观察节点为 R3。
2. 现场输入任意消息，点击“加密并发送”。图中的包号与密文标记跟踪同一个实际数据包，在 R3 自动暂停。
3. R3 展示实际截获的密文节选，点击“完整数据”可复制整个包。
4. 点击“原样转发”，包逐跳到达 R8 后点击“用接收端密钥解密”，看到输入消息的真实解密结果。
5. 点击“换条消息再试”。在 R3 点击“尝试篡改”实际翻转密文 1 位，再转发。R8 校验失败，不输出明文。
6. “设置”可选择明文对照、改观察节点、运行两条消息测试或修改密钥。错误接收密钥失败后，可以调整密钥重试同一个包。
7. 完整数据窗口里的独立解密只接收密文和密钥，不读取发送原文。
8. 点击发送路由器查看加密结构图；点各道工序查看这份包的实际数据，点 AES 再展开轮运算。输入、输出矩阵可以点选字节；切换块和轮次可跟踪整条消息。
9. 点击接收路由器查看接收结构图；篡改后默认定位到校验工序，两个实际标签逐字节对比，红色表示差异，原文输出为空。点击中间节点仅查看公开的传输包字段。
10. “实际收到的包”显示整份 raw 接收数据，保持原样可复制；点击下一步“解析包结构”才显示随机数、标签和完整密文。各工序的说明按做什么、为什么以及后续用途展开。
11. 每个输入注明对应来源，点击蓝色来源文字可回到该工序并高亮数据。计数器用蓝色标出沿用的 12 字节随机数、黄色标出本地追加的 4 字节计数值。GHASH 来源回溯可切换到对应密文块或上一累计步骤，认证标签可回溯到最后一个长度块结果；AES 输入矩阵可回溯到上一道轮运算输出。

AES-256-GCM 处理真实数据，每次生成新的随机数。传输沿当前网络路径在本机模拟；数据包中不包含明文或通信密钥。发送快照不会被后续草稿修改。

## 参考与核对

交互参考 [CrypTool AES 逐步演示](https://legacy.cryptool.org/en/cto/aes-step-by-step.html) 的字节依赖查看方式和 [AES-demo](https://github.com/harpoonsecurity/AES-demo) 的轮运算矩阵展示；算法按照 [NIST AES 标准](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.197-upd1.pdf) 与 [GCM 标准](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38d.pdf) 实现教学轨迹。验证涵盖 AES-256 标准向量、GCM 标签向量、Windows CNG 随机消息对照、末块不足 16 字节、中文消息、错误密钥及密文篡改。
